### 실행으로 확인한 내용

| 확인한 코드 | 결과 (go1.27.3) | 쓰인 곳 |
|---|---|---|
| 지문 프로그램(`greet`가 위, `main`이 `count()` 다음 `greet()` 호출) | `개수: 5` / `안녕 고퍼` | `mcq-trace-two-functions` 정답 a |
| 같은 프로그램에서 `main`의 호출 순서만 바꿈 | `안녕 고퍼` / `개수: 5` | 오답 b(파일 순서대로 실행된다는 오개념)의 출력이 실제로는 호출 순서를 바꿔야만 나옴 |
| `fmt.Println("개수:" + "5")`, `fmt.Println("안녕" + "고퍼")` | `개수:5` / `안녕고퍼` | 오답 c는 공백 없이 이어 붙일 때의 모양이고, `Println`은 값 사이에 공백을 넣음 |
| `fmt.Println("개수:", "2+3")` | `개수: 2+3` | 오답 d는 `2+3`을 따옴표 안에 넣어야 나오는 출력 |
| `main`이 부르지 않는 함수 `greet`가 있는 프로그램 | 컴파일 성공, `greet` 출력 없음 | "다른 함수는 불러야 실행돼요"(본문 Pitfall) |
| 지문 코드(`a := 5`, `b := a`, `a = a + 3`, `b = b * 2`, `fmt.Println(a, b)`)를 `main`에 넣음 | 컴파일 성공, `8 10` | `mcq-trace-copy` 정답 a, 오답 d(컴파일 오류)가 틀림 |
| 같은 코드에서 줄마다 `fmt.Println(a, b)` | `5 5` / `8 5` / `8 10` | 해설의 줄별 값, 오답 b(`8 16`)·c(`5 10`)가 틀림 |
| 위 프로그램 전체에 `gofmt -l` | 출력 없음(고칠 곳 없음) | 두 지문의 코드 모양 |

`fmt.Println("개수:", 2+3)`의 `2+3`은 `gofmt`가 인수 목록 안에서 붙여 쓰는 모양이고, `a = a + 3`처럼 문장 맨 바깥의 식은 띄어 쓰는 모양이라 두 지문 모두 그대로 둡니다.

## 문제별 판단

| 문제 | 유형·난이도 | 판단 | 이유 |
|---|---|---|---|
| `first-program.mcq-trace-two-functions` | mcq_single · L3 | 해설 보강 후 승인 | 정답 `개수: 5` / `안녕 고퍼`가 하나로 정해짐. 오답 b는 오개념 `go.mc.top-function-runs-first`, c는 `Println`의 공백, d는 식 계산을 각각 하나씩 틀린 출력이라 어느 지식이 비었는지 구분됨 |
| `variables.mcq-trace-copy` | mcq_single · L3 | 승인 | 정답 `8 10`이 하나로 정해짐. 오답 b(`b`가 `a`를 따라간다고 봄), c(`a = a + 3`을 놓침), d(`b := a`나 `=`가 오류라고 봄)의 이유가 실행 결과와 맞음 |

난이도 3 판단:

- **`mcq-trace-two-functions`.** 같은 레슨의 L1 문제는 "어느 함수부터 실행되나"(`mcq-where-execution-starts`)와 "`Println`이 무엇을 출력하나"(`check-println-two-values`)를 따로 묻습니다. 이 문제는 함수 두 개의 호출 순서와 두 줄의 출력 모양을 함께 맞혀야 하고, 파일 순서(`greet`가 위)와 호출 순서(`count`가 먼저)를 일부러 엇갈리게 둬 오개념이 실제로 걸리게 했습니다. 새 문법 없이 본문의 원리 두 가지를 묶는 문제라 도전 구간의 L3로 알맞습니다.
- **`mcq-trace-copy`.** 같은 레슨의 L2 문제는 `:=`·`=`·`==`를 고르거나 컴파일 여부를 판단하는 문법 구분 문제입니다. 이 문제는 변수 두 개를 네 줄에 걸쳐 따라가야 하고, `b := a`가 그 순간의 값을 넣는다는 점을 스스로 이끌어 내야 합니다. 본문은 다른 변수로 새 변수를 만드는 예를 직접 보여 주지 않지만, "`이름 := 값`은 새 변수를 만들고 처음 값을 넣어요"와 예제의 `price = price + 500`("지금 값에 더해 다시 넣어요")에서 풀 수 있는 범위라 L3로 알맞습니다.

두 문제 모두 힌트는 "어디서 시작하나 → 순서·그 순간의 값 → 출력 모양·값이 따라 바뀌는지"로 좁혀 가고, 셋째 힌트까지 정답 출력을 직접 말하지 않습니다. 개념 태그는 `mcq-trace-two-functions`가 실행 순서(`go.basics.program-structure`, 1)를 주로, 출력 모양(`go.basics.println`, 0.5)을 함께 다루므로 가중치 차이가 알맞습니다. `mcq-trace-copy`의 보기는 모두 공백이 들어간 모양이라 `Println`은 평가하지 않으므로 `go.vars.short-declaration` 하나만 둔 것이 맞습니다.

## 고친 내용

- **`mcq-trace-two-functions` 해설 셋째 단계.** 초안은 "`greet()`가 `안녕 고퍼`를 출력해요"만 적었습니다. 오답 c는 두 줄 모두 공백을 뺀 모양이라, 둘째 줄도 값이 두 개여서 공백이 들어간다는 점을 해설에 적었습니다.
- **두 레슨의 `practice.targetCount`를 2에서 3으로.** 문제를 승인하면 레슨마다 연습 문제(확인 문제 제외)가 3개가 되어 `pnpm content:check`가 "승인된 문제 3개 / 목표 2개" 경고를 냈습니다. 새 문제를 연습 세트에 넣는 것이 이번 추가의 목적이므로 목표를 실제 수에 맞췄습니다.
- 두 문제에 `review.status: approved`, `reviewedBy: ai:reviewer`를 넣었습니다. `draftedBy: ai:claude`는 그대로 둡니다.
- `pnpm content:build`가 `content/.published-slugs.txt`에 문제 slug 2개를 더했습니다.

## 그대로 둔 판단

- **`mcq-trace-copy`에 오개념 연결이 없는 것.** 오답 b(`8 16`)는 "`b := a` 뒤에도 `b`가 `a`를 따라간다"는 흔한 오해지만, 지금 오개념 목록과 레슨 Pitfall에 이 항목이 없습니다. 오개념을 새로 만들려면 레슨에 되짚을 Pitfall도 함께 있어야 해서, 이번에는 선택지 이유로만 설명합니다.
- **`8 16`이 "완전히 같은 변수"라는 오해와 다른 점.** `a`와 `b`가 완전히 같은 변수라고 보면 `16 16`이 나옵니다. `8 16`은 "`b`가 `a`의 값을 한쪽으로만 따라간다"는 모형의 답이라, 두 오해를 모두 담지는 않지만 보기 4개에서 정답이 하나로 정해지는 데는 문제가 없습니다.
- **"`main` 함수 안의 아래 코드" 형태의 지문.** 이전 문제(`multi-compile-errors`)와 같은 방식이고, 실행 확인은 `package main`과 `func main`으로 감싸서 했습니다.

## 남은 한계와 후속 제안

1. **코드를 실행하지 않는 문제만 있습니다.** 이번 확인도 검토자가 손으로 실행한 것이라, 코드 실행 검증을 도입할 때 두 지문의 출력(`개수: 5` / `안녕 고퍼`, `8 10`)을 자동 검사 대상에 넣길 권합니다.
1. **렌더링은 확인하지 않았습니다.** 보기 텍스트의 여러 줄 `text` 코드 블록이 선택지 화면에서 어떻게 보이는지는 앱에서 확인해야 합니다.
1. **도전 구간 문제가 레슨마다 하나뿐입니다.** 학습자가 같은 도전 문제를 반복해서 받게 되므로, 과정을 늘릴 때 난이도 3~4 문제를 더 두길 권합니다.
